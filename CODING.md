# Coding Conventions — PHPResticAdmin

## Общие

- **Версия PHP**: 8.1+, типизированные свойства, именованные аргументы, union types
- **Пространства имён**: PSR-4, `App\` → `src/`, `App\Tests\` → `tests/`
- **Без фреймворков**: вся инфраструктура находится в `src/Core/`. Не добавлять фреймворковые зависимости
- **Статический сервис-локатор**: статические методы `App::*()` выступают в роли сервис-контейнера. Не использовать `new` напрямую — всегда обращаться через `App`
- **Логирование через `App::log()`**: не использовать `error_log()` напрямую. Всегда `App::log($message, $level)` с правильным уровнем (0=critical, 1=info, 2=verbose)
- **Тестировать каждый новый класс**: создавать соответствующий тест в `tests/Unit/` до или сразу после написания класса
- **PHPStan level 1**: весь код в `src/` и `htdocs/` должен проходить проверку

## Именование

- **Классы**: PascalCase — `RepositoryController`, `ConfigStorage`, `CommandRunner`
- **Методы**: camelCase — `testConnection()`, `loadAll()`, `isLoggedIn()`
- **Переменные**: camelCase — `$repoId`, `$csrfToken`, `$availableCategories`
- **Приватные свойства**: camelCase — `private string $dataFile`
- **Константы**: UPPER_SNAKE_CASE
- **Ключи конфигов/переводов**: snake_case с точками — `repo.category.public`, `flash.repo_added`

## Структура кода

- Один класс — один файл. Имя файла совпадает с именем класса
- Порядок методов в классе: public → protected → private. Внутри каждой группы: конструктор → основные методы → хелперы
- Типизированные параметры и возвраты ВСЕГДА, где это возможно
- PHPDoc для массивов: `@param array{key: type, ...} $var` и `@return array{key: type, ...}`
- `declare(strict_types=1)` в новых файлах
- Никаких `else` после `return` (early return)

## i18n (всегда использовать `__()`)

- **ВСЕ пользовательские строки** должны проходить через `__()`
- В шаблонах: `<?= htmlspecialchars(__('key'), ENT_QUOTES, 'UTF-8') ?>`
- В контроллерах (flash-сообщения, ошибки): `__('key', ['{var}' => $value])`
- Строки, которые не нужно переводить: логи (`App::log()`), ключи массивов, технические идентификаторы
- Новые ключи переводов добавляются в ОБА файла: `data/lang/en.php` и `data/lang/ru.php`
- Ключи группируются по контексту: `repo.*`, `auth.*`, `flash.*`, `form.*`, `nav.*`, `error.*`

## Архитектурные соглашения

- **Контроллеры**: только диспетчеризация — получают Request, вызывают сервисы, возвращают Response. Никакой бизнес-логики
- **Storage**: работа с данными (YAML, сессии, конфиги). Не знают про HTTP
- **Core**: инфраструктура (роутер, сессия, CSRF, Request/Response). Не зависит от бизнес-логики
- **App.php — сервис-локатор**: все зависимости получаются через `App::something()`
- **Никаких `new` в контроллерах и шаблонах**: всегда через `App::*()` или внедрение в конструктор

## Пути репозиториев

- **Всегда использовать `RepositoryController::normalizePath()`** для новых путей
- Абсолютные пути (`/data/backup`) и URL-схемы (`s3://...`, `sftp://...`) сохраняются как есть
- Относительные пути (`my-repo`) получают префикс `repo_base_dir` из `settings.php` (по умолчанию `/backups`)

## Модель прав

Четыре права на уровне категории, два глобальных:

| Право    | Метод             | Уровень  | Что разрешает                              |
|----------|-------------------|----------|--------------------------------------------|
| `use`    | `canUse(cat)`     | Категория | Видимость в интерфейсе, базовые мета-данные (старый ключ) |
| `use_read` | `canUseRead(cat)` | Категория | Чтение контента: browse, download, export, список ключей (новый ключ) |
| `use_write` | `canUseWrite(cat)` | Категория | Запись в restic: backup, tag, maintenance, keys (новый ключ) |
| `edit`   | `canEdit(cat)`    | Категория | CRUD записи о репозитории: имя, путь, пароль, удалить (старый ключ) |
| `init`   | `canInit()`       | Пользователь | Инициализировать новые restic-репозитории   |
| `delete` | `canDelete()`     | Пользователь | Удалять репозитории                        |

Права независимы. Единственная импликация: `use_write` ⇒ `use_read`.
- `use` (старый ключ) — только видимость. НЕ даёт `use_read`.
- `edit` (старый ключ) — только CRUD. НЕ даёт ни `use_read`, ни `use_write`.
- `use_read` — без fallback'а: не задан → `false`.
- `use_write` — без fallback'а: не задан → `false`.
- `init` и `delete` — глобальные флаги `can_init`/`can_delete` на уровне пользователя
- `canMove(from, to)` требует `use_write` на обе категории
- Чекбокс «init» в форме добавления показывается только если `canInit()`
- Для пользователей без явных `can_init`/`can_delete`: logged-in → true, guest → false

## PHP в шаблонах

- `<?= ... ?>` для вывода, `<?php ... ?>` для управляющих конструкций
- Все переменные HTML-эскейпятся: `htmlspecialchars($var, ENT_QUOTES, 'UTF-8')`
- JS-строки из PHP: `json_encode(__('key'))` — автоматически экранирует кавычки
- Никакой бизнес-логики в шаблонах. Условия и циклы — только для отрисовки
